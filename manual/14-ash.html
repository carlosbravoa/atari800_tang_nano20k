14. ASH, the Atari shell

ASH is an optional operating system for this machine: power on and you land at a Unix-style command line instead of BASIC. From there you browse the whole SD card, mount disks, run programs and cartridges, manage files, edit text and, with the PC connected, fetch files from the internet and from FujiNet TNFS servers.

Turning it on (and off)

  1. Put ASH.CAR in the root of the SD card, with exactly that name. Download it from the ASH releases page.
  2. Open the OSD → Options → Boot → ASH → Save changes.
  3. Power-cycle (or Hard Reset). The machine boots straight into the shell:
ASH 1.3 TN - the Atari SHell
Type help for commands or basic to exit
D4:/$

Set Boot back to BASIC for the classic READY prompt. If ASH.CAR is missing or damaged, the machine silently boots to BASIC as before. You can also try ASH without changing the option: Cart → Attach → ASH.CAR.

Why a cartridge? ASH copies itself into RAM in a fraction of a second and then switches the cartridge off, so games see a normal machine with $A000–$BFFF free. RESET always brings you back to the prompt.

The prompt

The badge shows where you are: D1:/–D4:/ are the disk drives, H:/ is the SD card's /HDD folder, and SD:/games is a folder anywhere on the SD card. Change with cd, or type a drive alone (d2:).

  • Tab completes file names; ↑/↓ recall earlier commands; Ctrl+U clears the line; Break cancels a command.
  • Names with spaces go in double quotes: run "sd:/games/Candy Crunch.xex".
  • help lists every command on one screen.

Browsing and running

CommandWhat it does
ls [-l] [path]List a directory (* = runnable program, / = folder)
cd path, pwdChange / show the current directory: cd sd:/games, cd .., cd /
cat, xxd, fileShow a text file, a hex dump, or what a file is (for a .xex: its segments)
run file, or just the nameLoad and run a program: run sd:/games/pitstop.xex, or pitstop in its folder
dfDrives present and their free space

Disks, cartridges and rebooting

CommandWhat it does
mountShow what is on D1:–D4:, the cartridge slot and the boot setting
mount d1: sd:/disks/x.atrPut a disk image in a drive (any drive, D1:–D4:)
umount d1:Empty a drive
cart sd:/carts/x.carLoad a cartridge and boot it. Detach it from the OSD to come back to ASH (with Boot: ASH; otherwise you land in BASIC). Hard Reset restarts the game cartridge, like a power cycle.
rebootA full cold boot (ROMs reloaded, cartridge power-cycled)
basic / exitLeave ASH for Atari BASIC; BASIC's DOS command returns to ASH

Managing files

ASH replaces DOS. Its D: device stays available to BASIC and to programs you start from it (LOAD "D:GAME.BAS", saving high scores, and so on).

CommandWhat it does
cp src dstCopy between disks, h: and the SD card; dst may be a folder
rm, mvDelete (wildcards on disks: rm d1:*.bak), rename or move
mkdir, rmdirFolders (on MyDOS disks and on the SD card)
lock, unlockProtect files on a disk
format d2:Erase a disk to an empty DOS 2 disk (asks first)
edit fileA full-screen text editor: Ctrl+S saves, Ctrl+Q quits
lp filePrint a text file (it arrives on the PC, see PC Link)

Writable disks are DOS 2 / MyDOS format, 720 sectors, single or double density; larger disks are read-only from ASH.

Writing to the SD card

The SD card is read-only from ASH by default. Type sd rw to allow cp, mv, rm, mkdir and rmdir on sd: until the next cold boot; sd ro turns it off again and sd shows the state. Even with writes enabled, the firmware refuses to delete or overwrite the ROM files, atari.ini, ASH.CAR and any file that is currently mounted or attached.

Network, through the PC

With the board connected to a computer and ashterm running there in its interactive mode (see PC Link → ashterm), ASH can use the PC's internet connection. The Atari never talks to the network itself: it asks the PC, which fetches the file and delivers it through the USB link.

CommandWhat it does
dateThe PC's date and time (the Atari keeps counting afterwards; date sync asks again)
wget URL [dest]Download a file: onto a disk, into h:, onto the SD card (with sd rw), or - to show it
ls, cat, run, cpAlso accept http://, https:// and tnfs:// URLs
ls tnfs://tnfs.fujinet.online/ATARI
run tnfs://tnfs.fujinet.online/ATARI/_lobby.xex
cp tnfs://tnfs.fujinet.online/ATARI/games/x.atr sd:/disks/

TNFS is the file-server protocol used by FujiNet; public TNFS servers carry large software libraries that ASH browses like a disk. Without the PC program these commands answer no answer from the pc; everything else in ASH works with no PC at all.

Notes

  • A program that needs a specific DOS (SpartaDOS, a DOS 2.x internal call) may not run under ASH; boot that DOS from a disk instead.
  • ASH's resident part uses $0700–$1CFF (the same area as DOS 2.5), so anything that loads under DOS loads under ASH.
  • ASH also exists as a plain program and boot disk (ASH-TN.XEX, ASH-TN.ATR), and in a generic edition for any Atari XL/XE (ASH.XEX, ASH.ATR), without the board-specific features.
