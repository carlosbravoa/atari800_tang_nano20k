13. PC Link

El mismo cable USB-C que alimenta y graba la placa lleva también un enlace serial con el Atari: envía archivos, arranca programas, teclea, lee la pantalla y captura la impresora desde tu PC.

13.1 Qué es

El chip BL616 integrado en la placa hace de puente entre un puerto serial USB y el firmware del Atari. No hace falta ningún hardware adicional: el mismo cable USB-C que alimenta y graba (flashea) la placa es el enlace. Dos programas de la carpeta tools/ del repositorio lo usan, y ambos comparten una misma biblioteca de protocolo (atari_link.py):

  • tools/atari.py — la herramienta de línea de comandos.
  • tools/atari_gui.py — lo mismo, en una ventana de escritorio (Linux/Windows).

El Atari tiene su propia alimentación y sigue funcionando haga lo que haga el PC, así que un comando fallido siempre se puede reintentar sin riesgo. Las transferencias van a unos 11 KB/s y la máquina sigue funcionando mientras tanto (los discos montados siguen activos). El acceso del firmware a la memoria está diseñado con prioridad para el Atari; el impacto medido sobre la temporización de la máquina es cero incluso bajo carga continua de peek. La grabación de la placa no se ve afectada por el enlace.

13.2 Configuración inicial (una sola vez)

Linux

pip install pyserial
sudo apt install python3-tk     # desktop app only
sudo modprobe ftdi_sio          # if no /dev/ttyUSB* appears
# make the module load permanent:
echo ftdi_sio | sudo tee /etc/modules-load.d/ftdi_sio.conf

Windows

Instala pyserial de la misma forma (pip install pyserial). El driver FTDI VCP llega automáticamente por Windows Update. Las versiones de Python de python.org ya incluyen Tk, así que la aplicación de escritorio no necesita nada más.

¿Qué puerto?

La placa se enumera como un par de puertos seriales. El segundo puerto del par es el puente, y las herramientas lo eligen automáticamente. Si la detección automática alguna vez se equivoca, pasa -p con el nombre del puerto (por ejemplo -p /dev/ttyUSB1 o -p COM5); todos los comandos aceptan -p PORT. Luego comprueba el enlace:

python3 tools/atari.py ping        # -> "A8OK — bridge is alive (both directions)"
python3 tools/atari.py ports       # list candidate ports
Antes de grabarCierra log, kbd y la aplicación de escritorio antes de usar el programador de Gowin. Mantienen ocupado el puerto serial.

13.3 La herramienta de línea de comandos: atari.py

Ejecuta cada comando como python3 tools/atari.py <command> desde la carpeta del repositorio. Todos los comandos aceptan -p PORT.

ComandoQué haceEjemplo
portsLista los puertos seriales candidatos.atari.py ports
logMuestra en vivo el registro del firmware (mensajes de arranque, actividad SIO, líneas PRN: de la impresora). Ctrl-C lo detiene.atari.py log
ping¿Está vivo el puente? Espera recibir A8OK.atari.py ping

kbd controla la terminal en modo raw mediante llamadas de terminal Unix; en Windows usa en su lugar la pestaña Live Keys de la aplicación de escritorio.

13.4 La aplicación de escritorio: atari_gui.py

python3 tools/atari_gui.py
  • Connect (arriba) — puerto detectado automáticamente; muestra A8OK cuando el Atari responde.
  • Columna izquierda — Send file…, Run .xex… (con un campo Destination folder, por defecto PC, y una barra de progreso), Eject, Warm start, Cold boot, Ping. Los archivos de texto (.txt/.lst/.bas) enviados desde aquí se convierten automáticamente a finales de línea ATASCII. Un .xex ejecutado de forma remota aparece en la línea D1: del OSD y se puede desconectar desde cualquiera de los dos lados.
  • Pestaña Log — salida del firmware en vivo; Clear / Save….
  • Pestaña Type — escribe o carga un listado BASIC y luego Type it on the Atari (línea por línea, con recuperación automática ante fallos del USB).
  • Pestaña Printer — todo lo que imprime el Atari se acumula aquí (§13.6): Save as .txt, Save as PDF, Print…, Clear.
  • Pestaña Live Keys — haz clic en el recuadro y teclea directamente en el Atari (incluidos Backspace/Esc/Tab/Enter). Pulsa F12 en el teclado real para recuperar la máquina; la aplicación se desconecta limpiamente.

13.5 Reglas del tecleo

  • El tecleo llega a la máquina solo mientras el menú OSD está cerrado (un menú abierto se traga las pulsaciones, la misma regla de enmascaramiento que el teclado físico).
  • Los caracteres se asignan según la distribución del teclado Atari.
  • La velocidad es de unos 18 caracteres por segundo. Después de cada RETURN el firmware espera 250 ms, porque BASIC tokeniza la línea mientras su buffer de teclado solo guarda un carácter; los listados de varias líneas llegan intactos.
  • Las sesiones largas de type pueden, ocasionalmente, hacer caer el enlace USB. Las herramientas se recuperan solas y reintentan; para programas grandes es preferible la vía H: + ENTER de §13.11.

13.6 Captura de impresora

El firmware emula la impresora P: (dispositivo SIO $40, estilo 820). Todo lo que imprime el Atari — LPRINT desde BASIC, PRINT #n a P:, LIST "P:", la función de impresión de AtariWriter — llega al PC como texto. Funciona en una máquina estándar sin drivers, porque el manejador de P: vive en la ROM del sistema operativo.

  • Con la herramienta de línea de comandos, el texto impreso aparece como líneas PRN: en atari.py log.
  • En la aplicación de escritorio se acumula en la pestaña Printer: Save as .txt, Print… a la impresora de tu sistema, o Save as PDF para una reproducción de matriz de puntos 5×7 fiel a la época (se eliminan los márgenes del procesador de textos y el ancho se ajusta automáticamente al documento).

13.7 El disco duro D4: (HDD.ATR)

Una imagen de disco llamada exactamente HDD.ATR en la raíz de la tarjeta SD se monta automáticamente en D4: en cada encendido, sin ninguna interacción con el OSD. Es el destino natural para los archivos que intercambias con el PC: copia una imagen a la tarjeta con python3 tools/atari.py send mydos_big.atr HDD.ATR y luego apaga y vuelve a encender, porque el montaje automático se ejecuta una sola vez al iniciar el firmware. status muestra el montaje y el registro dice boot: hdd mounted on D4. Los formatos, la combinación con un DOS (se recomienda MyDOS) y las reglas de seguridad se tratan en el capítulo 6, Discos.

13.8 La carpeta compartida H:

H: es un dispositivo CIO (del mismo tipo que P:, E: y K:), no un disco, así que DOS no lo lista ni necesita hacerlo. Los archivos escritos en H: quedan como archivos normales en /HDD, en el sistema de archivos FAT de la tarjeta SD: la misma carpeta en la que escribe el PC con send … HDD/NAME. Es el puente para archivos de texto y de datos entre los dos mundos.

Instálalo primero, desde el PC:

python3 tools/atari.py hdd-install
# -> "H: installed at $0900-$0CB2 (above MEMLO), MEMLO raised to $0D00."

El instalador lee MEMLO y coloca el manejador justo por encima (con un DOS residente arrancado simplemente queda más arriba), y luego sube MEMLO más allá de su final. El manejador vive en la RAM del Atari y su alcance es la sesión: RESET lo borra, así que vuelve a ejecutar hdd-install para restaurarlo.

Teclea NEW en BASIC justo después de instalarBASIC solo vuelve a leer el MEMLO elevado con NEW; hasta entonces su área de programa sigue solapándose con el manejador. Instala primero, NEW, y luego ENTER o teclea tu programa.

Úsalo desde BASIC:

REM --- write ---
OPEN #1,8,0,"H:NOTES.TXT"
PRINT #1;"WRITTEN FROM BASIC"
CLOSE #1

REM --- read back ---
OPEN #1,4,0,"H:NOTES.TXT"
DIM A$(40):INPUT #1,A$:PRINT A$
CLOSE #1

REM --- store/recall a program (plain ATASCII, PC-readable) ---
LIST "H:PROG.LST"
ENTER "H:PROG.LST"

REM --- directory with sizes ---
OPEN #1,6,0,"H:"
DIM D$(40)
FOR I=1 TO 999:INPUT #1,D$:PRINT D$:NEXT I
CLOSE #1

REM --- delete ---
XIO 33,#1,0,0,"H:NOTES.TXT"

Modos de OPEN: 4 = lectura, 8 = escritura, 9 = añadir al final, 6 = directorio, 12 = actualización.

13.9 Red (N:) y módem (R:)

Dispositivo de red N: — prototipo

Existe en el árbol de fuentes, como prototipo funcional, un dispositivo SIO N: retransmitido a un procesador de red que corre en el PC: una aplicación real del tiempo de FujiNet ha obtenido y mostrado datos en vivo en el banco de pruebas. Todavía no está a nivel de versión publicada bajo carga sostenida y está previsto para una versión posterior.

N: sigue siendo un prototipo y aún no tiene un procedimiento para el usuario final. Lo que se ha demostrado en el banco de pruebas, con atari_net.py en el PC actuando como procesador de red: una aplicación del tiempo de FujiNet obteniendo y mostrando datos en vivo, un lector de noticias descargando titulares en vivo, y sesiones de BBS con BobTerm a través de la vía del módem R:. Cuando se publique, esta sección incluirá los pasos de configuración.

Módem 850 R: para BobTerm — en desarrollo, opcional, desactivado por defecto

BobTerm (y otros programas de terminal para módem 850) puede marcar a una BBS telnet real a través del cable USB-C. El firmware responde al sondeo del manejador de arranque en frío del sistema operativo y sirve el manejador 850 real de Altirra (compatible con FujiNet); tools/atari_net.py --modem es el módem del lado del PC (comandos Hayes AT, telnet).

  1. Actívalo: OSD → Options → Modem (R:) → ON (se guarda con Save changes como modem=1). En OFF (el valor por defecto) la función no tiene ningún efecto sobre el uso normal: el firmware permanece en silencio ante el sondeo del sistema operativo, así que un arranque para jugar no cambia en nada.
  2. Consigue los dos binarios de Altirra. Son obra de Avery Lee para Altirra, redistribuidos por el proyecto FujiNet, y deliberadamente no se incluyen en este repositorio. Descárgalos del repositorio del firmware de FujiNet, en 
    fujinet-firmware/data/webui/device_specific/BUILD_ATARI/850handler.bin
fujinet-firmware/data/webui/device_specific/BUILD_ATARI/850relocator.bin
    y colócalos en tools/fujinet_850/. Tamaños esperados: manejador 1281 bytes, relocalizador 341 bytes. Revisa su licencia original antes de redistribuirlos.
  3. Cópialos a la tarjeta SD — el firmware los transmite desde /PC/850HAND.BIN y /PC/850REL.BIN durante la carga inicial del manejador en el arranque en frío (solo cuando la opción Modem está en ON): 
    python3 tools/atari.py send tools/fujinet_850/850handler.bin   PC/850HAND.BIN
python3 tools/atari.py send tools/fujinet_850/850relocator.bin PC/850REL.BIN
  4. Como alternativa, python3 tools/atari.py r-install instala el manejador R: en una sesión en marcha, por encima de MEMLO (teclea NEW en BASIC después; RESET lo borra, vuelve a ejecutarlo para restaurarlo). Luego inicia atari_net.py --modem en el PC y ejecuta BobTerm.
EstadoEn desarrollo: parte del texto se corrompe con ráfagas rápidas de la BBS. Utilizable para sesiones de BBS; todavía no a nivel de versión publicada bajo carga sostenida.

13.10 Telemetría y depuración remota

El puente responde en todo momento, incluso en la pantalla de error de ROM, así que una máquina que no arranca se puede examinar y rescatar desde el PC.

  • status devuelve una línea que empieza por ST. Campos: u: tiempo de funcionamiento del firmware en ms; bs: etapa de arranque (0 inicio, 1 SD ok, 2 opciones, 3 ROMs intentadas, 4 en marcha); rom: resultado de la carga de ROMs; x: hay un .xex virtual activo; m: cuatro dígitos, uno por unidad D1:–D4: (1 = montada); c:/s:/st: último comando, sector y estado SIO; e: contador de errores SIO; cn: el canario de pila del firmware; más los contadores hd: y nt: del manejador H: y del dispositivo de red.
  • screen vuelca la pantalla de texto de 40×24: unos "ojos remotos" sobre el prompt READY o la salida de tu programa.
  • peek/poke inspeccionan y modifican la RAM del Atari en vivo (con suma de verificación). Observa cómo avanza el reloj de jiffies en 0x12 para comprobar que el 6502 está vivo; haz un poke en 0x2C8 para un borde rosado.
  • log muestra los marcadores de etapa de arranque: boot: sd ok → boot: roms 0 → boot: running (y boot: hdd mounted on D4 cuando hay un HDD.ATR).
  • Rescate ante error de ROM: si la máquina se detiene en la pantalla de error de ROM, envía con send los archivos de ROM que faltan por el cable y pulsa una tecla en el Atari para reintentar.
  • Cómo leer las respuestas: una respuesta de status nombra la etapa en la que el firmware quedó trabado. Un silencio serial total significa que la máquina nunca llegó al firmware: apágala y vuelve a encenderla.

13.11 Recetas

Pegar un programa BASIC corto

Cierra el OSD y luego:

python3 tools/atari.py type mygame.bas
# or from a pipe:
cat mygame.bas | python3 tools/atari.py type -

En el Atari: RUN (y SAVE "D4:MYGAME.BAS" si hay un DOS arrancado).

Cargar un programa largo sin teclearlo

Envía el listado como archivo y cárgalo con ENTER (necesita H: instalado, es decir, una sesión de BASIC):

python3 tools/atari.py send --text mygame.lst HDD/MYGAME.LST
ENTER "H:MYGAME.LST"
RUN

Enviar y ejecutar un programa compilado

python3 tools/atari.py run build/demo.xex     # sends + cold-boots into it

El programa aparece en la línea D1: del OSD; atari.py eject lo quita.

Llevar un listado del Atari al PC

Todavía no hay descarga de archivos a través del puente, pero el Atari puede imprimir hacia el PC:

LIST "P:"

Llega como texto en atari.py log o en la pestaña Printer de la aplicación de escritorio (luego Save as .txt).

Compartir archivos de datos en ambos sentidos

  • PC → Atari: python3 tools/atari.py send --text data.txt HDD/DATA.TXT, y luego OPEN #1,4,0,"H:DATA.TXT" en el Atari.
  • Atari → PC: escribe en H: desde BASIC (OPEN #1,8,0,"H:OUT.TXT" …). El archivo queda ahora en /HDD/OUT.TXT en la tarjeta SD; el PC lo lee directamente la próxima vez que pueda leer la tarjeta. (Está previsto un comando get para el puente.)

Depuración remota

python3 tools/atari.py status                 # boot stage, mounts, SIO health
python3 tools/atari.py screen                 # what's on the Atari screen now
python3 tools/atari.py peek 0x12 3            # jiffy clock (is it alive?)
python3 tools/atari.py poke 0x2C8 0x35        # tint the border pink

13.12 Limitaciones

Usa las herramientas que vienen con tu versión del firmwareDesde la v3.2.1 el puente solo acepta comandos enmarcados (un byte de sincronización, el comando y un byte de verificación), de modo que los bytes sueltos en el enlace USB ya no pueden provocar un reinicio ni una escritura en memoria. La carpeta tools/ de la misma versión publicada siempre coincide; un atari.py antiguo frente a un firmware más nuevo simplemente no obtiene respuesta.
  • El alcance de H: es la sesión: RESET lo borra; vuelve a ejecutar hdd-install. Se instala por encima de MEMLO y convive con un DOS residente, pero BASIC solo toma el MEMLO elevado con NEW.
  • Todavía no hay descarga de archivos desde la tarjeta SD a través del puente. El texto Atari → PC va por la vía de la impresora (LIST "P:" / LPRINT); está previsto un comando get.
  • El montaje automático de HDD.ATR se ejecuta una sola vez al iniciar el firmware. Después de enviar uno nuevo con send, apaga y vuelve a encender la placa.
  • type necesita el OSD cerrado.
  • Las sesiones largas de type pueden, ocasionalmente, hacer caer el enlace USB; las herramientas se recuperan solas y reintentan, pero la vía H: + ENTER lo evita para programas grandes.
  • Problema conocido: F12 puede no responder mientras hay una sesión serial con el PC en curso; el botón S2 sigue abriendo el OSD (ver el capítulo 15).

13.13 Si el puente deja de responder

RecuperaciónSi el chip del puente deja de responder tras una tormenta de USB (por ejemplo, una sesión de tecleo muy larga), desconecta el cable USB de la placa, espera diez segundos y vuelve a conectarlo. El lado del Atari no se ve afectado.
