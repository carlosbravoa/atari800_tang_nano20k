6. Disks

Disk images on the SD card are served to the Atari as SIO floppy drives D1: to D4: — you can read, write, format and swap them while the machine runs.

Supported formats

ExtensionWhat it is
.atrThe standard Atari disk image: a 16-byte header followed by the sectors. The header gives the sector size.
.xfdA raw sector dump with no header. The geometry is taken from the file size: 92,160 bytes = single density, 133,120 bytes = enhanced density, 183,936 bytes = double density. Any other size that is a multiple of 128 is treated as a 128-byte-sector image; other sizes are refused (Unsupported .xfd size).

Copy your images anywhere on the SD card — the root or any folder, long names are fine — and attach them from the OSD.

Densities

All three classic densities work:

  • SD — single density, 720 sectors of 128 bytes (90K).
  • ED — enhanced density, 1040 sectors of 128 bytes (130K).
  • DD — double density, 256-byte sectors. Both file conventions for DD images are handled automatically — the packed layout and the full-boot-area layout (the firmware tells them apart from the file size). MyDOS 4.5 images boot.

Drives D1: to D4:

The Atari sees four drives. Only the first two are shown in the OSD:

DriveWhere it is managed
D1:, D2:The OSD main menu (items 1) D1: and 2) D2:), and the PC link.
D3:, D4:Not in the OSD. D4: is the automatic HDD.ATR "hard drive"; D3: and D4: also serve automounts and the PC link.

Use D2: for data disks or for disk 2 of a two-disk game. When a game asks for the next disk, attach it to D1: live instead.

Mounting and swapping

Open the OSD, select the drive, choose Attach (.atr/.xfd/.xex)... and pick the image (the browser is described in The OSD menu). The image is in the drive at once; nothing is rebooted. To replace it, attach another one; to empty the drive, choose Detach. The main menu's D1:/D2: lines always show what is mounted.

Because the Atari keeps running behind the menu, a load that was in progress continues while you browse.

Booting from a disk

  1. Copy the .atr to the SD card.
  2. Power on — the Atari boots to BASIC — then press F12 or S2 to open the OSD.
  3. 1) D1: → Attach (.atr/.xfd/.xex)... → pick the image → Enter/Fire.
  4. Back on the main menu, choose 7) Hard Reset. The Atari cold-boots from D1: (into DOS, or into the game).

Most DOS disks and bootable games work. If a disk expects BASIC to be out of the way, use 4) Boot to OS (No BASIC) instead of Hard Reset — it boots with OPTION held.

Writing, and read-only images

Writes are reliable since v2.4: SAVE from BASIC, saving from DOS, copying files, and formatting all work on mounted images, on every drive. A few rules keep your data safe:

  • PC read-only attribute. Images copied from a PC sometimes carry the FAT "read-only" attribute. The firmware clears it when it can and mounts the disk writable. If it cannot get write access, the disk is mounted read-only: the pop-up Disk is read-only / Writes will fail (144) appears, the drive line shows (RO), the drive reports write-protect in its status, and any write returns error 144 — exactly like a write-protected floppy.
  • The same image on two drives. If you mount an image that is already mounted in another drive, the second mount is made read-only automatically (and marked (RO)). Two writable handles on one file can corrupt the SD card's own filesystem, so this is refused on purpose. Mount a copy under another name if you really need two writable instances.
  • Out-of-range sectors are rejected like a real drive would; they can no longer grow the image file.
Older firmwareBefore v2.4, writing could corrupt disk images and even the SD card's FAT filesystem. If your card was damaged by an earlier version, reformat it (full FAT32) and copy your files again. See Known issues.

New blank disk

Each drive menu has 2) New blank disk (90K). It creates an empty, unformatted single-density ATR (90K, 720 × 128-byte sectors) in the root of the SD card, named BLANK01.ATR, BLANK02.ATR, … up to BLANK99.ATR (first free name), and mounts it in that drive. Any disk that was in the drive is detached first.

The new image is unformatted. Boot a DOS and use its format command on that drive — the SIO FORMAT commands are implemented, so DOS 2.5's "Format disk" and friends work — and you have a writable disk without ever touching a PC.

DOS formatting

The disk FORMAT commands used by DOS (single and enhanced density) are supported on any mounted image, not just blank ones. Formatting rewrites the whole image, so make sure the right drive is selected in your DOS.

HDD.ATR — an always-on hard drive on D4:

Put a disk image named exactly HDD.ATR (case does not matter) in the root of the SD card. At every power-on the firmware mounts it on D4: automatically — no menu interaction, ever. Your DOS simply sees a permanent extra drive: list it, save and load files, and everything survives reboots.

  • Which image? Any .atr works, but a MyDOS-formatted image is the ideal choice: MyDOS can address images up to 16 MB, a genuinely big hard disk.
  • Making one from the PC: copy any large MyDOS ATR to the SD card as HDD.ATR (or send it over the cable with python3 tools/atari.py send mydos_big.atr HDD.ATR), then power-cycle — the automount runs once at firmware start.
  • Making one on the Atari: use New blank disk on a drive to get a 90K ATR and rename it to HDD.ATR later on a PC.
  • Backup is one file: keep a copy of HDD.ATR on your PC. If the disk ever gets scrambled, copy it back and power-cycle.

Without an HDD.ATR, or with the wrong kind

The automount is fail-safe and opt-in; it can never stop the machine from booting.

  • No HDD.ATR on the card: nothing happens. D4: is simply not there, and a DOS that asks for D4: gets "drive not present". A corrupt file or a non-ATR file with that name is checked and quietly not mounted.
  • A valid image formatted for a different DOS than the one you boot: D4: does mount and its sectors are served faithfully, but your running DOS may not read it — a garbled directory, "not a DOS disk" or 0000 FREE SECTORS. Typical mismatches: a big MyDOS image while you booted DOS 2.5 (DOS 2.5 caps at 90K/130K and, by default, only polls D1:/D2: — it needs POKE 1802,15 to even look at D4:), or a SpartaDOS image read by MyDOS and vice versa.
Recommended pairingFormat HDD.ATR with the same DOS you boot. MyDOS 4.5x is the recommended choice: format the image with MyDOS and boot MyDOS, and its full capacity is usable.

The H: device — a folder shared with the PC

Separate from the disk drives, the H: device is a CIO device (a peer of P:, E: and K:) whose files are plain files in the /HDD folder of the SD card — the same folder the PC link writes to, so the Atari and the PC share one file space for text and data. It is installed from the PC with atari.py hdd-install and used from BASIC with the usual OPEN #1,8,0,"H:NOTES.TXT", LIST "H:PROG.LST" / ENTER "H:PROG.LST" and so on. Setup and examples are in PC Link.
