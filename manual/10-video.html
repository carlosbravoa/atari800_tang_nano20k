10. Video

The picture leaves the board over HDMI as a 720-line signal that is locked to the Atari's own frame timing — steady, tear-free and only a couple of scanlines behind the machine.

What comes out of the HDMI port

The Atari draws a 352×240 picture at the NTSC rate. The board scales it by an exact integer factor of 3 into a 1056×720 active area inside a custom 1216×786 raster, and sends that over HDMI. Every Atari pixel becomes a crisp 3×3 block; nothing is resampled.

The output is genlocked: the pixel clock is frequency-locked to the core, so exactly one output frame is produced for every Atari frame. Because the frame and line counts are whole numbers, the picture never drifts, jitters by a line or tears. There is no frame buffer — the Atari's lines are captured a few at a time into a small line buffer and read out straight away, which is why the latency is only about 1–2 scanlines. Your display sees an HD, 720-line signal.

PropertyValue
Atari picture352 × 240
Active output1056 × 720 (3× in both directions)
Total raster1216 × 786
Frame rateNTSC, 59.94 Hz — one output frame per Atari frame
Latency~1–2 scanlines, no frame buffer

NTSC only

This is an NTSC machine: 262 lines per frame at 59.94 Hz, and the exact NTSC machine clock. There is no PAL mode and no switch for one. Software written for PAL will run, but at NTSC timing; see PAL titles below for what that means in practice.

Display compatibility

You need an HDMI 1.3 or later monitor or TV and an ordinary HDMI cable. Note that staying jitter-free requires a non-standard timing: the signal is 1056×720 active, declared as 720p, rather than exact CEA 720p, because the Atari's frame rate does not divide evenly into any standard HDMI mode. Most modern TVs and monitors accept it on a direct connection, but some strict or older displays — and pass-through equipment such as HDMI splitters, AV receivers and capture cards — may reject it ("no signal", "unsupported" or "out of range").

If your display refuses the signalAn older release (v1.1) produces a fully CEA-standard 720p signal at the cost of higher latency; it is available from the project's releases page and can be flashed instead.

Displays tried so far: several TVs, standard LCD computer monitors, an external OLED display and a 9-inch 4:3 screen built around an iPad panel, all of which accepted the picture without any issue. Capture devices (HDMI-to-USB sticks) have not been tried yet; if you use one, its behaviour is worth reporting either way.

Scanlines

A CRT-style scanline effect can be blended into the picture. Open the OSD, choose Options and step Scanlines through OFF, 25%, 50% and 75%. The change applies immediately, over the live picture, so you can compare settings on the game you are playing. Save changes stores it in atari.ini as scanlines= (0–3; default 0 = OFF). See Options & atari.ini.

Horizontal position

If your display crops the left or right edge, or the picture sits off-centre, slide it with Options → H position. Use ← / → (or the joystick left/right) to move it; the range is 0 to 48 and the picture moves live as you adjust. It is saved as hpos= (default 0).

HDMI drop on a cold start

On some cold power-ons the HDMI output may briefly drop and then recover — the display loses the signal for a moment and comes back — while the Atari itself keeps running underneath. This is a known behaviour of the video output at power-up; it is not a crash and needs no action. If the picture does not return, see Troubleshooting.

PAL titles on an NTSC machine

A few demanding PAL games show garbled sprites, a jumpy or jittery image, or freezes during play. Two known examples:

  • Tiger Attack (Atari UK, 1988) — sprites garbled; occasional freezes.
  • Astro Droid (Red Rat Software, 1987) — vertical jitter; sprites garbled or wrong colours.

The most likely cause is that these are PAL games running on an NTSC-only machine. Both are British budget titles built around PAL ANTIC timing (312 lines at 50 Hz) and aggressive per-frame vertical fine scrolling — writing VSCROL mid-frame, often from display-list interrupts. On an NTSC machine (262 lines at 60 Hz) the scroll regions, interrupt line targets and sprite positions no longer line up, which produces exactly these symptoms. A real Atari, or MiSTer, set to NTSC behaves the same way. It is not a loading problem and not a fault in the board's memory or video path: NTSC-friendly scrollers such as River Raid, which use coarse scrolling updated once per frame, are unaffected.

PAL support is not plannedSwitching to PAL is not a simple flag. It changes the machine clock (1.7734 vs 1.7898 MHz), which cascades through the memory and pixel clocks and the genlocked video mode (1216×786 = 3 × 262 lines; PAL's 312 lines would need a different mode and PLL). It is effectively a second complete clock and video configuration, and given that these are obscure PAL titles on an NTSC reference machine, PAL support is deferred.
