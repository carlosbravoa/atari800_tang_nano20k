3. Getting started

From an empty SD card to a BASIC prompt, a booted disk and a running cartridge in a few minutes.

1. Prepare the SD card

Format a micro-SD card as FAT32 (32 GB or smaller) and put the two ROM files in the root directory. Everything else is optional:

/
├── ATARIXL.ROM   ← Atari XL/XE OS ROM, exactly 16384 bytes
├── BASIC.ROM     ← Atari BASIC ROM, exactly 8192 bytes
├── HDD.ATR       ← optional: auto-mounts on D4: at every boot — your
│                    permanent "hard drive" (any ATR; MyDOS-formatted is ideal)
├── HDD/          ← optional: the H: device's folder — files here are
│                    shared between the Atari (H:) and the PC link
├── games/        ← your .atr disks and .car/.rom cartridges, any folders,
└── ...              long filenames fine
ROMs are not includedYou must supply your own ATARIXL.ROM and BASIC.ROM. Names are matched case-insensitively (atarixl.rom works too), but the sizes must be exact. The firmware loads both ROMs from the card at every power-on.

2. Flash the bitstream

Download the zip from the latest release on GitHub and unpack atari800_tn20k.fs. That one file is the whole machine: the firmware is baked into the bitstream, so there is no separate firmware to flash and nothing else to write to the board. The ROMs, disks and cartridges live on the SD card, not in the flash.

The board is flashed over its own USB-C cable; no programmer or adapter is needed. The onboard chip presents itself to the PC as a two-channel FTDI device: channel A is the JTAG programmer, channel B is the serial port the PC Link uses. Both tools below write the bitstream into the board's external flash, so it survives power-off. You flash once per release, not every time you power on.

Before flashingClose anything that holds the board's serial port: the PC Link desktop app, an atari.py log or kbd session, a terminal program. The SD card and HDMI can stay connected.

Linux (and macOS): openFPGALoader

The free, open-source openFPGALoader is the simplest way and needs no account or licence. Install it from your distribution, then flash:

# Debian / Ubuntu / Mint
sudo apt install openfpgaloader
# Fedora
sudo dnf copr enable mobicarte/openFPGALoader && sudo dnf install openFPGALoader
# Arch
sudo pacman -S openfpgaloader
# macOS
brew install openfpgaloader

# then, with the board plugged in:
openFPGALoader -b tangnano20k -f atari800_tn20k.fs

-b tangnano20k selects the board and -f writes the external flash. The tool prints the erase and write progress and ends with Done; the board reconfigures itself and, with a card inserted, boots to READY a few seconds later.

If you get unable to open ftdi device or a permissions error, your user cannot open the USB device yet. Either run the same command with sudo, or install the udev rule once so you never need to: copy 99-openfpgaloader.rules from the openFPGALoader sources into /etc/udev/rules.d/, run sudo udevadm control --reload-rules && sudo udevadm trigger, add yourself to the plugdev group with sudo usermod -a -G plugdev $USER, and log in again.

Windows: Gowin Programmer

openFPGALoader has no ready-made Windows build, so on Windows use Gowin's own Programmer. It is free: no licence is needed for programming, only a Gowin account to download. Sipeed also mirrors a standalone Programmer package with the USB drivers included, which is the easiest route:

  1. Install the Programmer. Get it either from Sipeed's mirror at dl.sipeed.com/shareURL/TANG/programmer (Programmer plus drivers, no account) or from Gowin's download page (create a free account; the Education edition needs no licence, and the Programmer is inside it). Install the USB driver when the installer offers it.
  2. Plug the board in with the USB-C cable and wait about ten seconds for Windows to finish installing the device. Device Manager should list two USB Serial Converter entries (A and B); no COM port is needed for flashing.
  3. Open the Programmer and click Scan Device (the magnifier icon). It should find one device, GW2AR-18C. If it finds nothing, see the troubleshooting list below.
  4. Configure the operation. Double-click the device row (or use Edit → Configure Device) and set:
    • Access Mode: External Flash Mode
    • Operation: exFlash Erase, Program thru GAO-Bridge (on some Programmer versions the entry is called exFlash Erase, Program; either works)
    • Programming Options → File name: your atari800_tn20k.fs
    • External Flash Options → Device: Generic Flash, Start Address: 0x000000
    Leave User Code and IDCODE alone. Click Save.
  5. Program. Click the Program/Configure button (the green play icon). The progress bar runs through erase, program and verify; the status column shows Success when done. The board reconfigures itself and boots to READY.
SRAM Mode is not what you wantThe Programmer also offers SRAM Mode / SRAM Program. That loads the bitstream into the FPGA directly, which works for a quick test, but it is gone at the next power-off. Use External Flash Mode so the machine boots on its own.

If the Programmer does not find the board:

  • Install the driver from the Sipeed programmer package and reconnect the cable. Windows sometimes needs a second attempt after the first plug-in.
  • Close any program that has the board's COM port open (the PC Link app, a terminal). The JTAG channel and the serial channel share the chip.
  • Try another USB-C cable or port. Charge-only cables carry no data, and a marginal cable makes the board disconnect and reconnect (see Troubleshooting).
  • In the cable settings, keep the frequency at 2.5 MHz or lower; higher JTAG clocks are unreliable through the onboard chip.

openFPGALoader can also run on Windows through MSYS2 (package mingw-w64-ucrt-x86_64-openFPGALoader) after replacing the driver of USB interface 0 with WinUSB using Zadig. It works, but it is more steps than the Programmer and a wrong Zadig choice can take the serial port down with it, so it is only worth it if you already use MSYS2.

Check that it took

After either method: LED5 starts blinking slowly (the firmware heartbeat), then LED3 lights when the ROMs have loaded from the card, and the screen shows READY. If LED5 does not blink, the flash did not complete: run it again. If LED5 blinks but nothing else happens, the SD card is the problem, not the flash; see step 3 below.

3. First power-on

  1. Insert the SD card and connect the HDMI cable to the monitor.
  2. Power the board from the USB-C port.

A healthy boot looks like this:

  • The screen shows the Atari BASIC READY prompt. No menu appears — the machine auto-boots straight to BASIC.
  • LED3 (pin 18) is solid on: the ROMs loaded and the Atari is running.
  • LED5 (pin 20) blinks at about 0.8 Hz: the FPGA heartbeat.
No keyboard yet?Press the on-board S2 button to open the menu. A DB9 joystick on port 1 (up/down and fire) can drive the whole OSD on its own.

The ROM-error screen

If the firmware cannot load the ROMs, the Atari does not start and the menu shows the failure instead of BASIC. Check that:

  • the SD card is FAT32 formatted and fully inserted;
  • ATARIXL.ROM (16384 bytes) and BASIC.ROM (8192 bytes) are in the root directory.

Fix the card, reinsert it and press S1 (hardware reset) or power-cycle the board. With the PC Link you can also rescue it without touching the card: the bridge answers at the ROM-error screen, so you can send the missing ROMs over the cable and press a key to retry.

4. Boot a disk in 60 seconds

  1. Copy an .atr disk image anywhere on the SD card (root or a subfolder).
  2. Power on — the Atari boots to BASIC.
  3. Open the OSD with S2 (or F12 on a keyboard).
  4. Choose 1) D1: → Attach disk..., browse to your .atr, press Fire / Enter to mount it.
  5. Choose 4) Boot to OS (No BASIC) — the Atari cold-boots from the mounted disk with BASIC disabled (for example into DOS). Only a disk that needs BASIC resident wants 7) Hard Reset instead.

The mounted image shows on the D1: line of the menu. Use D2: for data disks or disk 2 of multi-disk games, or swap D1: live when a game asks for the next disk. See Disks.

5. Run a cartridge in 60 seconds

  1. Copy a .car (or a 2/4/8/16 KB raw .rom) to the SD card.
  2. Open the OSD with S2 / F12.
  3. Choose 3) Cart: → Attach cartridge... → pick the file — it boots immediately.

To get back to a multi-game cartridge's menu after a game, use 7) Hard Reset. F9 is the real RESET key and usually lands in BASIC — that is what a real Atari does too. See Cartridges.
