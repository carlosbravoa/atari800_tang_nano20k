15. Known issues and limitations

Behaviour that is documented and expected — some of it faithful to the real machine, some of it a genuine limitation of this port.

Known issues

RESET inside a multi-game cartridge lands in BASIC or Self Test

This is faithful, not a bug. The XL/XE cartridge port has no reset line, so a cartridge cannot see the RESET key. A multicart that switched itself off to run a game (Atarimax compilations do this) is still off after RESET, and the XL OS then boots BASIC — or Self Test if BASIC is disabled. Altirra does exactly the same on F5. This applies to Soft Reset in the OSD and to the F9 hotkey.

Use Hard Reset instead: since v3.0 it power-cycles the emulated cartridge (bank 0, enabled) and brings the multicart menu back, like a real power cycle (Altirra Shift+F5). See Cartridges.

F12 can be unresponsive while a PC serial session is engaged

With the PC Link actively engaged (a live keyboard session or an app connection), the F12 key on the physical keyboard sometimes does not open the OSD. Workaround: the S2 button on the board always works, and closing the PC session restores F12 immediately. Under investigation.

Some PAL vertical-scrolling games glitch (this is an NTSC-only machine)

A few demanding titles show garbled sprites, a jumpy or jittery image, or freezes during play:

  • Tiger Attack (Atari UK, 1988) — sprites garbled; occasional freezes.
  • Astro Droid (Red Rat Software, 1987) — vertical jitter; sprites garbled or wrong colours.

Most likely cause: these are PAL games, and this build is NTSC-only. Both are British budget titles built around PAL ANTIC timing (312 lines / 50 Hz) with aggressive per-frame vertical fine scrolling. Run that on an NTSC machine (262 lines / 60 Hz) and the scroll regions, DLI line targets and sprite positions no longer line up. A real Atari, or MiSTer, set to NTSC behaves the same way. It is not a loading problem (Astro Droid runs from cartridge) and not a memory or video-path bug in the port. NTSC-friendly scrollers such as River Raid are unaffected.

PAL support is not planned. Switching the core to PAL changes the machine clock and cascades through the whole clock and genlocked video chain — effectively a second complete clock and video configuration.

Cold-start HDMI drop

On some cold starts the HDMI output may briefly drop and recover while the machine keeps running. See Troubleshooting.

Fixed in earlier releases

  • v2.4: disk writes were unreliable (ERROR 139, corrupted images, and in extreme cases damage to the SD card's own filesystem) — fixed and hardware-verified. If an earlier version damaged your card, reformat it (full FAT32) and recopy your files.
  • v2.3.1: ANTIC mode-8 fine scrolling stuttered (Ninja Commando / Draconus marquees) — an upstream core bug, fixed here.

Limitations

  • .xex loader and page $0600–$07FF — a program that loads into page 6/7 can clash with the running loader, which lives there. Relocating the loader to high RAM is a possible future fix. See Executables.
  • N: network device / internet — a working prototype exists (an N: SIO device relayed to a PC-side network processor; a real FujiNet weather app has fetched live data on the bench), but it is not yet release-grade under sustained load.
  • R: serial device (850 / modem) — work in progress, opt-in and default OFF. BobTerm can dial a live telnet BBS over the USB-C cable: the firmware serves the Altirra 850 handler and tools/atari_net.py --modem is the PC-side modem. Enable it in OSD → Options → Modem (R:) (it needs the two Altirra .bin files on the SD card — see tools/fujinet_850/README.md). Some text garbles under fast BBS bursts. When OFF it has zero effect on normal use.
  • Joystick paddles — analogue pot inputs are not implemented. Powered controllers (paddles, mice, active autofire pads) are not supported.
  • The!Cart 32/64/128 MB — cannot fit the 8 MB SDRAM and are rejected. Cartridges are supported up to 4 MB (MegaCart); unsupported CAR types show their type id on screen. See Cartridges.
  • Machine is NTSC only — a runtime PAL/NTSC switch is on the roadmap, but PAL is not supported today.
