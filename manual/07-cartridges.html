7. Cartridges

Cartridge images up to 4 MB load from the SD card and boot exactly like a cartridge plugged into a real XL — including banked multicarts.

Formats: .car and raw .rom

FormatMax sizeLimited by
.car4 MBThe 4 MB cartridge window in the board's SDRAM (the chip is 8 MB; the rest holds Atari RAM and the ROMs)
.rom (raw)16 KBA raw dump carries no mapper information, so only the simple unbanked sizes — 2, 4, 8 and 16 KB — can be loaded

A .car file is a raw dump with a small header that names the cartridge type (its bank-switching scheme). 52 CAR types are supported, from plain 8K/16K carts to XEGS, switchable XEGS, AtariMax, OSS, SDX, Williams, SIC!, Turbosoft and MegaCart up to 4 MB. The full list is in the Appendix.

A raw .rom larger than 16 KB is refused with Raw .ROM must be 2/4/8/16K — use a .CAR instead: without a header the firmware cannot know which mapper the cartridge uses. Convert bigger dumps to .car with any Atari cartridge tool so the type is stored in the header.

Why the 4 MB limit

The whole cartridge must be resident in SDRAM. Bank switching is a real-time decision made by the 6502 — a write to the mapper register followed immediately by a read from the new bank — so there is no opportunity to stream banks from the SD card on demand (SD latency is about a thousand times too slow for that window). Everything up to MegaCart 4 MB (.car type 63) fits. The!Cart images (32, 64 and 128 MB) cannot fit in the 8 MB SDRAM and are rejected with Cartridge too large (>4MB).

Attaching a cartridge

  1. Open the OSD (F12 or S2) and select 3) Cart:.
  2. Choose 1) Attach cartridge... — the browser shows only .car and .rom files and folders.
  3. Pick the file. The cartridge is loaded into SDRAM and the Atari cold-boots straight into it; the menu closes by itself.

The main menu's Cart: line shows the attached cartridge from then on. Attaching another cartridge replaces it and cold-boots again.

If the file cannot be used, a pop-up explains why and you are returned to the browser:

Pop-upMeaning
Unsupported CAR type nThe header names a cartridge type the core does not implement. The number is the CAR type id — please report it if you think it should be supported.
Cartridge too large (>4MB) / does not fit 8MB SDRAMThe image is bigger than the 4 MB window (for example The!Cart).
Raw .ROM must be 2/4/8/16K / use a .CAR insteadA raw dump of a banked cartridge — convert it to .car.
Not a valid .CAR fileThe file has the .car extension but no CART header.

Detaching a cartridge

3) Cart: → 2) Detach removes the cartridge and cold-boots back to BASIC (the Cart: line returns to None). With nothing attached the menu just says No cartridge inserted.

Multicarts, RESET and Hard Reset

Banked multicarts (Atarimax compilations, for example) show a menu, then switch the cartridge off to run the chosen game from RAM. Getting back to the menu works differently for the two kinds of reset — and both behave like real hardware:

ResetWhat the cartridge seesWhere you land
7) Hard Reset (v3.0)A power cycle: the cartridge is re-enabled and put back on bank 0.The multicart's menu comes back, like a real power cycle (Altirra Shift+F5).
6) Soft Reset / F9Nothing. The XL/XE cartridge port has no reset line, so a cartridge cannot see the RESET key. A multicart that switched itself off stays off.The XL OS boots BASIC — or the Self Test if BASIC is disabled — exactly like a real Atari and like Altirra's F5. This is faithful, not a bug.
Rule of thumbTo return to a multicart's menu, use Hard Reset, not F9.

Cartridges and BASIC

A cartridge at $A000 occupies the same address range as the built-in BASIC, so while it is attached BASIC is replaced — the machine boots the cartridge, as a real XL does. This also means that 4) Boot to OS and 5) Boot to BASIC both boot the cartridge while one is attached; to get BASIC back, detach the cartridge first.

Supported CAR types

The 52 supported CAR type ids, with their names, are listed in the Appendix. Unsupported types are rejected on screen with their id, so you always know which one you hit.
